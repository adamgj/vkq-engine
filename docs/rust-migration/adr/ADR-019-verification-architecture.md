# ADR-019: Verification architecture and C-build retirement criteria

**Status:** Accepted
**Date:** 2026-08-16
**Tags:** —

## Context

"100% backwards compatible" is only meaningful if it is *measured*. The migration's central bet is that every port can be differentially verified against the live C implementation. That requires the verification machinery to exist **before** the first port, and requires a defined end to the C build's oracle role.

## Decision

**Built in Phase 0, gating every subsequent phase:**

1. **Demo-determinism harness** — headless playback over a versioned corpus (id1, Hipnotic, Rogue, 2021 re-release, Arcane Dimensions, Copper, Alkaline, Quoth, CSQC mods); per-frame hash chain over canonical state (edict arena bytes, RNG state, client sim vars). Per-{OS, arch} goldens generated by the C build (ADR-010).
2. **Savegame/config byte-diff** — scripted saves at fixed points, byte-compared; cross-load matrix in both directions (ADR-005).
3. **Progs trace oracle** — `-Dtrace` builds in both languages emit per-instruction/builtin records, diffed; builtin-table dump diff per progs.dat; `tools/c2rust-oracle/` as semantic tiebreaker.
4. **Protocol goldens + interop matrix** — byte-diffed session captures; 4-way C/Rust client×server localhost tests across 15/666/999 × PRFL × PEXT; demos recorded by both engines byte-diffed.
5. **Fuzzing** — cargo-fuzz targets for every parser; differential (C-via-FFI vs Rust) where feasible; corpora versioned in-repo or via CI cache.
6. **Float-formatter conformance** — stratified per-PR + scheduled-exhaustive f32 sweeps vs platform `snprintf` (ADR-005).
7. **Sound PCM-hash**, **renderer SSIM/validation/timedemo** (ADR-015), **sanitizers** (ASan/UBSan on C, Miri on pure crates, TSan/loom for tasks), **mod bench** smoke per release.

**Process rules:** goldens are regenerated only from the C reference build at a tagged commit, never hand-edited; a failing gate blocks merge for the affected subsystem; every phase exit re-runs the *full* suite, not just the subsystem's gates.

**C-build retirement criteria (Phase 9):** the C-only CI leg is removed only after (a) all phases 0–9 exit criteria hold with Rust `main()`, (b) one full release cycle ships from the mixed/Rust build with no compat regressions reported against the gates, and (c) the final C-capable commit is tagged `c-reference/final` with documented instructions for rebuilding the oracle. Golden regeneration after retirement uses that tag.

## Consequences

- Compatibility becomes a continuously enforced property with an audit trail, not an aspiration.
- Phase 0 is front-loaded work with no visible porting progress — accepted as the foundation everything else stands on.
- The corpus (game data, mods, demos) includes non-redistributable content; CI uses hashes/derived artifacts where licensing forbids storing the originals, and developers need local copies for full runs (documented in the harness README when built).
